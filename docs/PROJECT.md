# 上市公司年报摘要 RAG 问答系统

面向 15 家 A 股半导体/新能源产业链公司 2025 年年度报告摘要的问答系统。
核心思路：**数值走结构化查询（可校验），叙述走混合检索（可引用），
意图由模型理解、路由由代码裁决**。

> 本文是速览版。完整架构、代码地图、裁决规则见 [交付物/02-框架设计详解.md](交付物/02-框架设计详解.md)。
> 本地小模型部署见 [finqa4b-deploy.md](finqa4b-deploy.md)。

---

## 1. 技术架构

```
                       用户问题
                          │
                  ┌───────▼────────┐
                  │  QueryRouter   │  小模型做 Schema Linking → 意图 DSL
                  │ 模型提议/代码裁决│  白名单校验通过才生效，否则回退规则
                  └───────┬────────┘
                          │
      ┌───────────┬───────┴───────┬────────────┬──────────┐
      ▼           ▼               ▼            ▼          ▼
  ┌────────┐ ┌─────────┐  ┌────────────┐ ┌────────┐ ┌────────┐
  │  sql   │ │ growth  │  │    rag     │ │  both  │ │  chat  │
  │SQLite  │ │两年算同比│  │  Milvus    │ │先答后补│ │ 闲聊   │
  └───┬────┘ └────┬────┘  └─────┬──────┘ └───┬────┘ └───┬────┘
      │           │             │            │          │
      ▼           ▼             ▼            ▼          ▼
  确定性渲染   确定性计算   双链路召回   SQL 先输出   直接回答
  1.1–1.3s     1.2s        +RRF+精排    再让模型补
  零幻觉                     top-8       定性分析
      │           │             │            │          │
      └───────────┴─────────────┴────────────┘          │
                                │                       │
                    ┌───────────▼───────────┐           │
                    │ DashScope qwen3.8-max │◀──────────┘
                    │ temperature=0         │
                    └───────────────────────┘
```

**为什么数值不交给生成模型**：财务数字要求「每一格都对」，而小模型会改写数字
（实测把 `322,045 户` 写成 `32,204,500 户`）。所以数值题由模板渲染，模型只负责叙述性内容。

## 2. 核心设计

### 2.1 表格解析：规则优先，期间类型由指标决定

- 74 张 HTML 表格 → **681 条结构化事实**（年度/时点 441 条 + 季度 240 条）
- **期间类型不看表头**：表头写「2025年」，但「总资产」是年末时点、「营业收入」是年度区间。
  用指标定义覆盖表头文字，才能正确处理表头不规范的公司
- **增减列不入库**：可由两年数值反算，且口径混乱（`16.5` / `12.83%` / `增加0.9个百分点`）
- **单位统一**：入库全部换算为「元」（千元 ×1000、万元 ×10000），保留 `unit_raw` 供溯源

### 2.2 三重校验保证数值零容错

| 校验 | 方法 | 结果 |
|---|---|---|
| C1 | 四季度之和 == 年度值 | **45/45 通过**（15 家 × 营收/净利润/经营现金流） |
| C2 | 增减% 可由两年数值反算 | 13/15 精确，2 家为四舍五入差异 |
| C3 | 与正文披露数字交叉比对 | 抽样通过 |

C1 是最强的一道：任何列错位、单位错乱、数字截断都会让等式不成立。

### 2.3 检索：双链路 + RRF + 精排

| 环节 | 实现 | 作用 |
|---|---|---|
| 稠密召回 | `bge-base-zh-v1.5`（768 维），各召回 50 条 | 语义（"赚钱能力" ↔ "净利润"） |
| 稀疏召回 | Milvus 内置 BM25，各召回 50 条 | 字面（"GaN"、"注1" 这类 embedding 表达不出的词） |
| 融合 | `RRFRanker(k=60)`，取 20 条 | 把两路分数量纲问题转成排名问题 |
| 精排 | `bge-reranker-large` cross-encoder | query-doc 交互打分，取 top-8 进 prompt |

**chunk 策略**：按标题切 section，目标 400 字、重叠 60 字、硬上限 600 字；
表格替换为占位符，图片以文件名做图注单独成块。共 **512 块**。

**关键细节**：chunk 的 `text` 前面必须拼上最后一级标题。否则短节被合并后标题只留在
`section` 元数据里，而向量化只看 `text`，这个词就永远检索不到。

### 2.4 路由：模型做提议者，代码做裁决者

意图识别不是硬编码匹配，而是**受限的 Schema Linking**：

```
用户问题 ──▶ 本地小模型（rLLM-FinQA-4B）
              │  输入：15 家公司 + 13 个指标的枚举清单（不含任何数值）
              │  输出：意图 DSL（intent / companies / metric / year / quarter）
              ▼
         代码裁决器
              │  公司必须在白名单、指标必须映射到 metric_code
              │  相对时间「去年」由规则换算（模型算不准）
              │  字段与意图不自洽 → 降级
              ▼
           Route ──▶ 参数化 SQL / 向量检索
```

**为什么这样分工**：模型负责「理解」——口语、省略、指代、复合问题都能接住；
代码负责「决定」——每个字段都要落在白名单内，模型判断错了最多是选错枚举值，
不会越权查询，也不会把幻觉字段带进 SQL。模型全程不产生 SQL、不产生数字。

**裁决规则**：

| 情况 | 处理 |
|---|---|
| 公司不在 15 家白名单 | 丢弃该实体 |
| 指标不在 13 个 code 内（如「毛利率」） | 降级为文本检索，回答「未披露」 |
| 模型漏了指标（「挣钱」→ 净利润） | 用规则的口语映射补 |
| 「去年 / 前年」 | 由规则按报告年换算，不采信模型 |
| 年份超出库内覆盖 | 用户明确问才保留（照实答未披露），模型编的则回落 |
| 季度但该指标无季度数据 | 丢掉季度，退化为年度 |
| 模型不可用 / 输出非法 JSON | 回退纯规则路由 |

规则路由仍然保留，作为离线基线、兜底路径和单测对象。

| 通道 | 触发条件 | 示例 |
|---|---|---|
| `sql` | 公司 + 指标，无叙述词 | 中芯国际 2025 年营业收入 |
| `growth` | 指标 + 增速意图 | 2025 年营收增速最快的是哪家 |
| `rag` | 只有公司 / 只有叙述意图 | 中芯国际的行业地位如何 |
| `both` | 指标 + 叙述意图 / 多公司对比 | 比亚迪营收增长的原因 |
| `chat` | 问候、闲聊 | 你好 |

三个实现细节：

1. **叙述意图时禁口语映射**：「盈利模式」不能被 `盈利 → 净利润` 吃掉
2. **多公司匹配**：「比亚迪和中芯国际谁更赚钱」要能返回两家
3. **历史继承**：追问「2024年的呢」时，从最近 300–400 字历史补公司/指标

### 2.5 LLM 兜底：规则失手时让模型判断结构

15 份摘要的表格全部能被规则解析，但生产环境会遇到没见过的表（合并单元格、多组表头、多余列）。
这时不抛异常，也不让模型从零读表：

```
规则解析 → 校验 → 通过 → 入库
              │
              └─ 失败 → LLM 输出「列语义 + 行映射」（不含数值）
                        → 代码按标注重新取数 → 再校验 → 仍失败进人工队列
```

**触发条件**：

| 编号 | 条件 |
|---|---|
| T1 | 表头识别失败（含 `20xx` 的单元格 < 3） |
| T2 | 列数 ∉ {4,5} |
| T3 | 指标行映射命中率 < 60% |
| T4 | 四季度之和 ≠ 年度值 |

**边界**（这是设计的关键）：

- LLM 的输入**只有表头文字和行名文字**，一个数值都不给
- LLM 的输出**只有结构**，不产生任何数字
- 数值仍由 `normalize_number` 从原格子取，期间类型仍以 `metric_dict` 为准
- 拿到标注后**必须重新校验**，不通过就进人工队列

所以即使模型判断错了，最多是「取错列」，T4 会拦下来，不会把错数字写进库。

**实测**（`tests/test_llm_fallback.py`）：给中芯国际主表人为加一列「备注」触发 T2，
模型返回 `confidence=0.98`、2 组表头、11 行，修复后三个关键指标与正常表完全一致。

开启方式：`python create_data/build_index.py --all --llm-fallback`

### 2.6 答案溯源

每个答案末尾标出处，**由代码追加，不让模型写**（prompt 至今禁止模型输出「来源1」——
模型会编造不存在的来源，也会把编号抄错位置）。

| 通道 | 标注形式 |
|---|---|
| `sql` / `growth` | `来源：中芯国际2025年年度报告摘要.md 第 3 张表` |
| `rag` | `来源：1. 中芯国际2025年年度报告摘要.md §一、行业地位；2. ...`（去重取 3 条） |
| `both` | 数值段用「来源：…第 N 张表」，叙述段用「参考资料：…§章节」 |

两条例外：

- **推算值不标来源**：负债合计是「总资产 − 净资产」算的，标成披露表会误导
- **文件名要归一**：`new_Data` 里是「公司名：原始文件名.md」，部分原始名自身含公司名
  （`中芯国际：中芯国际2025年…`），个别带 OCR 后缀（`.pdf_by_PaddleOCR-VL-1.6.md`），
  `TableQuery.doc_label()` 统一处理

溯源字段本来就在库里（`fact.source_doc/source_table`、`chunk.doc_path/section`），
之前只是没渲染到答案里。

## 3. 实测结果

| 指标 | 结果 | 说明 |
|---|---|---|
| 表格解析校验 | **45/45** | 四季度之和 = 年度值 |
| 结构化事实 | **681 条** | 15 家 × 74 张表 |
| 切块 | **512 块** | 全部 ≤ 600 字 |
| 检索 Recall@5 | **100%**（12/12） | 人工出题 + 关键词命中判定 |
| 检索 MRR@10 | **0.944** | 平均命中位置 1.06 |
| 意图裁决单测 | **24/24** | 白名单、越界、往年、相对时间全覆盖 |
| 端到端准确率 | **21/21** | 含 3 道「必须拒答」的越界题 |
| 意图识别耗时 | **1.1–1.3s**（中位 1.17s） | 本地 4B 推理 + JSON 约束解码 |
| SQL 通道耗时 | **1.1–1.3s** | 意图识别 + 确定性渲染（数值本身零延迟） |
| growth 通道耗时 | **≈1.2s** | 两年数据算同比，不经过生成模型 |
| both 通道耗时 | **12–45s** | 先出 15 家排名，再让云端补分析 |
| RAG 通道耗时 | **10–27s** | 检索 ≈0.5s + 云端生成长文本 |

意图识别是这里唯一的固定开销。若要压到近零，可把 `INTENT_MODE` 切为 `rule` 走纯规则基线，
或用「规则高置信时跳过模型」的混合模式。

**生成模型**：DashScope `qwen3.8-max-0902`，`temperature=0`。
离线场景可切本地 `rllm-finqa-4b:q4`（4.4B，Q4_K_M，2.7 GB，5.1 GB 显存），
把 `.env` 的 `LLM_PROVIDER` 改为 `ollama` 即可，部署见 [finqa4b-deploy.md](finqa4b-deploy.md)。

## 4. 快速开始

```bash
# 1. 构建结构化索引（681 facts → SQLite）
python create_data/build_index.py --sqlite

# 2. 构建向量索引（512 chunks → Milvus）
python create_data/build_index.py --milvus

# 3. 跑测试
python tests/test_intent_dsl.py           # 意图裁决器 24 条（不需模型，最快）
python create_data/test_table_parser.py   # 表格解析
python create_data/test_chunker.py        # 切块
python tests/test_retrieval.py            # 检索 Recall/MRR（需 Milvus）
python tests/test_llm_fallback.py         # LLM 表格兜底（需 Ollama）
python tests/test_e2e.py                  # 端到端 21 题（需 Milvus + 云端 LLM）

# 4. 启动服务
python main.py                             # http://127.0.0.1:8000
```

**Milvus 两种模式**，通过 `.env` 的 `MILVUS_ENDPOINT` 切换：

| 模式 | 配置 | 特点 |
|---|---|---|
| Lite | `db/milvus.db` | 零依赖，单文件，单进程锁 |
| standalone | `http://127.0.0.1:19530` | 需 Docker，多客户端，支持分区 |

```bash
docker compose -f docker-compose.milvus.yml up -d    # 起 standalone（单容器）
```

两种模式的**数据不共享**，切换后必须重跑 `build_index.py --milvus`。
分词器随 URI 自动切换（Lite → `jieba`，standalone → `chinese`）。

## 6. 已知边界

- **数据边界**：摘要只披露 12 个核心指标，问「毛利率 / 存货 / 研发费用」时应回答「未披露」而不是编造（已纳入评测）
- **公司边界**：固定 15 家；年度数据覆盖 2023–2025（含财报里的往年对比列），季度数据只有 2025 年，新增公司需重跑 `build_index.py`
- **表格边界**：前十名股东、债券表未入库（字段异构、问答价值低）
- **规模边界**：512 个 chunk 下检索全量召回，无需分片；数据量上到十万级需引入分区与副本
- **意图边界**：多跳推理（「比它营收高的有几家」）模型不稳定，会落到 `narrative` 走文本检索
